codediff.nvim                                 *codediff.txt* *codediff.nvim* *codediff*

CodeDiff provides VSCode-style diff rendering with two-tier highlighting,
supporting both side-by-side and inline (unified) layouts.

This help file is usage-focused. For installation, build, and development
details, see README.md.

==============================================================================
QUICK START                                           *codediff-quickstart*

After installing the plugin and running |:CodeDiff|, you can:
- Browse changed files (default explorer)
- Compare the current file with a git revision
- Compare two files or directories

==============================================================================
COMMANDS                                                  *codediff-commands*

:CodeDiff [args]
    Open the CodeDiff UI. See |codediff-usage| for available modes.

:CodeDiff install
:CodeDiff install!
    Manually install/update the C library (optional; auto-installed on use).

==============================================================================
USAGE                                                       *codediff-usage*

File explorer mode (git status by default):
>vim
  :CodeDiff
  :CodeDiff HEAD~5
  :CodeDiff main
  :CodeDiff abc123
  :CodeDiff main HEAD
<

Git diff mode (current buffer vs revision):
>vim
  :CodeDiff file HEAD
  :CodeDiff file HEAD~1
  :CodeDiff file abc123
  :CodeDiff file main
  :CodeDiff file v1.0.0
  :CodeDiff file main HEAD
<

Requirements:
- Current buffer must be saved to a file
- File must be in a git repository
- Git revision must exist

Behavior:
- Left buffer: git revision (readonly)
- Right buffer: current buffer (readonly)
- Opens in a new tab
- Async operation (won't block Neovim)

File comparison mode:
>vim
  :CodeDiff file file_a.txt file_b.txt
<

Directory comparison mode:
>vim
  :CodeDiff ~/project-v1 ~/project-v2
  :CodeDiff dir /path/to/dir1 /path/to/dir2
<

Shows files as Added (A), Deleted (D), or Modified (M) based on file size and
modification time. Select a file to view its diff.

File history mode:                                    *codediff-history*
>vim
  :CodeDiff history
  :CodeDiff history HEAD~10
  :CodeDiff history origin/main..HEAD
  :CodeDiff history HEAD~20 %
  :CodeDiff history --reverse
<

Line-range history (visual selection):            *codediff-history-line-range*

Visually select lines and run `:CodeDiff history` to show only commits that
modified the selected line range. Uses `git log -L` under the hood.
>vim
  :'<,'>CodeDiff history
  :'<,'>CodeDiff history HEAD~10
  :'<,'>CodeDiff history --reverse
<

Each commit is compared against its parent by default. Use --base to compare
every commit against a fixed reference instead:
>vim
  :CodeDiff history --base WORKING
  :CodeDiff history --base HEAD
  :CodeDiff history --base main
  :CodeDiff history HEAD~10 -b WORKING %
<

Options:
  --reverse, -r   Show commits oldest first
  --base, -b      Compare each commit against a fixed revision instead of
                  its parent. Accepts any git revision (HEAD, branch name,
                  commit hash) or WORKING for the current working tree.

Git merge tool:
>sh
  git config --global merge.tool codediff
  git config --global mergetool.codediff.cmd 'nvim "$MERGED" -c "CodeDiff merge \"$MERGED\""'
<

CONFIGURATION                                        *codediff-configuration*

                                                      *codediff-layout*
Diff layout~

CodeDiff supports two diff layouts:

  `"side-by-side"` (default): Two panes with synchronized scrolling.
  `"inline"`: Single pane with deleted lines shown as virtual overlays.
              Includes treesitter syntax highlighting on virtual lines.

Set the layout in your config:
>lua
  require("codediff").setup({
    diff = { layout = "inline" },
  })
<

                                                      *codediff-moved-code*
Moved code detection~

CodeDiff can detect blocks of code that moved within a file, similar to
VSCode's experimental `diffEditor.experimental.showMoves` feature.

Enable in your config:
>lua
  require("codediff").setup({
    diff = { compute_moves = true },
  })
<

When enabled:
- Moved lines get a distinct background highlight (CodeDiffLineMove)
- Sign column shows box-drawing characters (┌│└) marking the moved block
- Annotation lines (⇄ moved: L3-8 → L11-16) appear above each moved block
- Press `gm` on a moved block to temporarily align it with its counterpart

The `gm` keymap disables scrollbind and positions both panes so the moved
block appears at the same visual row. Moving the cursor outside the block
or switching windows restores normal scrollbind.

TOGGLING LAYOUT                                   *codediff-toggle-layout*

Press `t` in a diff view to toggle between side-by-side and inline layout.
The current file is re-rendered in the new layout automatically. This works
in all modes (explorer, history, standalone).

The toggle keymap can be customized:
>lua
  require("codediff").setup({
    keymaps = {
      view = {
        toggle_layout = "t",  -- or false to disable
      },
    },
  })
<

PR REVIEW GROUPS                                      *codediff-review-groups*

In revision mode (|:CodeDiff| main, main HEAD, main...HEAD) the explorer groups
changed files by rules the repository commits in `.github/pr-groups.json` (or
`.github/pr-groups.jsonc`). Status mode and directory comparison are unchanged.
The format is shared with the github-fast-pr browser extension. >json

  {
    // Groups are shown in this order (highest viewPriority first)
    "groups": [
      { "name": "Backend", "paths": ["^server/", "\\.go$"] },
      { "name": "Tests", "paths": ["_test\\.go$"], "matchPriority": 2 },
      { "name": "Lockfiles", "paths": ["\\.lock$"], "autoViewed": true },
    ],
    "generated": { "viewPriority": -3 },
    "ungrouped": { "viewPriority": 5 }
  }
<
Format ~
  `groups`: array of { name, paths, autoViewed?, matchPriority?, viewPriority? }
  `generated`: { matchPriority?, viewPriority? }
  `ungrouped`: { viewPriority? }
  `//` and `/* */` comments and trailing commas are accepted. An invalid
  config (bad JSON, missing name/paths, bad pattern, wrong types) is ignored
  with one error message.

Patterns ~
  Each entry of `paths` is a JavaScript regular expression matched unanchored
  and case-sensitively against the repo-relative path. With `node` on `$PATH`
  (`regex_engine = "auto"`), patterns run as native JavaScript regexes, so
  every JavaScript construct works. Without node, a built-in translator to Vim
  regex is used. It supports:
  `^ $ .`, escapes such as `\.`, `\d \w \s`, character classes, groups
  (including `(?:...)` and `(?<name>...)`), lookahead `(?=...)` `(?!...)`,
  lookbehind `(?<=...)` `(?<!...)`, alternation `|`, and the quantifiers
  `* + ? {n,m}`. The translator rejects (the config is invalid) inline flags
  like `(?i)`, `\b`, and backreferences.

Assignment and order ~
  A file belongs to the matching group with the highest `matchPriority`; ties
  go to the earlier group. Default `matchPriority`: 1 for `autoViewed` groups,
  0 otherwise. Files matching nothing are `Ungrouped`.
  Groups sort by `viewPriority`, highest first, ties in config order.
  Defaults: 0 for groups, -1 for `Ungrouped`, -2 for `autoViewed` groups.
  Empty groups are hidden.

Generated ~
  Files marked `linguist-generated` in `.gitattributes` form an auto-viewed
  `Generated` group, with or without a config. Attributes are resolved by git,
  read from the base revision on git 2.40+ and from the working tree on older
  git.

Config source ~
  The config is read from the base revision of the comparison (the merge-base
  for `main...HEAD`), never from the reviewed branch. Set
  `explorer.pr_review.groups` in |codediff-configuration| to a Lua table with
  the same shape to override the repo file for every repo.

Without a config and without generated files the usual single `Changes` group
is shown.

Options (`explorer.pr_review`) ~
  `enabled`           Set false to restore the plain `Changes` group.
  `groups`            Lua table overriding the repo config.
  `auto_mark_viewed`  Files in autoViewed/Generated groups start viewed.
  `collapse_groups`   Start every review group collapsed. Fully viewed
                      groups (usually auto-viewed ones) always start
                      collapsed. User collapse state is kept across
                      refreshes.
  `skip_viewed`       `]f` / `[f` skip viewed files.
  `viewed_icon`       Marker for viewed files.
  `regex_engine`      How `paths` patterns are matched. `"auto"` (default):
                      `node` when it is on `$PATH`, so patterns are native
                      JavaScript regexes exactly as in github-fast-pr; else
                      the built-in translator to Vim regex (see Patterns).
                      `"node"`: node only; without node the config is ignored
                      with an error. `"vim"`: translator only.
  `debug`             Log each step of loading review groups (`[codediff:review]`
                      messages printed to |:messages|): why groups were skipped, each
                      `git show <base>:<path>` attempt and its git error, the
                      parse result, the groups built and the generated files.
                      No messages at all means the comparison is not in
                      revision mode.

Viewed state ~
                                                       *codediff-viewed*
  In revision mode files can be marked viewed (also on the single `Changes`
  group). Viewed files show `viewed_icon` before the file icon and are dimmed
  (`CodeDiffExplorerViewed`). Group headers read `Backend  1/4  +70 -15`:
  viewed/total (`CodeDiffExplorerGroupProgress`) and, with `show_line_stats`,
  the summed +ins -del of the unviewed files. The plain group reads
  `Changes  1/5`. Directories show the same remaining +ins -del. Auto-viewed
  group names are drawn with `CodeDiffExplorerGroupAutoViewed` (yellow).
  A fully viewed directory or group is dimmed, shows `viewed_icon` and its
  full +ins -del dimmed, and collapses when it becomes fully viewed (and on
  open), and opens again as soon as a file in it is unviewed (by you, or
  because its diff changed on refresh). Reopening or closing one by hand
  sticks until its viewed state changes again.

  `v` (`keymaps.explorer.toggle_viewed`)
      Toggle the file, directory or group under the cursor. If any file below
      is unviewed all become viewed, otherwise all become unviewed.
  `<leader>v` (`keymaps.view.toggle_viewed`)
      Toggle the file shown in the diff panes.
  `]f` / `[f`
      Skip viewed files (also inside collapsed groups, which are expanded to
      show the target) when `skip_viewed` is true. With every file viewed,
      "All files viewed" is shown and the current file stays.

  Auto-viewed and Generated groups start viewed when `auto_mark_viewed` is
  true; un-viewing such a file sticks for that file diff.

  A file is viewed only while both sides of its diff are unchanged (keyed by
  path, old blob and new blob). A new commit touching the file, or a working
  tree edit when comparing against the working tree, makes it unviewed; other
  commits do not. State is shared by reviews with the same file diff
  whatever the revisions are named.

  State is stored per repository in `stdpath("state")/codediff/viewed/`
  (JSON, pruned after 90 days). If it cannot be read or written, one warning
  is shown and the review continues in memory. Status mode and directory
  comparison have no viewed state; the keymaps do nothing there.

                                                *CodeDiffViewedChange*
  Toggling fires `User CodeDiffViewedChange` with data
  `{ tabpage, paths, viewed }`; `viewed` is the new state of `paths`. >lua

    vim.api.nvim_create_autocmd("User", {
      pattern = "CodeDiffViewedChange",
      callback = function(ev)
        print(vim.inspect(ev.data.paths), ev.data.viewed)
      end,
    })

HIGHLIGHT GROUPS                                     *codediff-highlight-groups*

CodeDiff defines highlight groups matching VSCode's diff colors:
- CodeDiffLineInsert - light green background for inserted lines
- CodeDiffLineDelete - light red background for deleted lines
- CodeDiffCharInsert - deep/dark green for inserted characters
- CodeDiffCharDelete - deep/dark red for deleted characters
- CodeDiffFiller - gray foreground for filler line slashes (///)
- CodeDiffLineMove - background for moved lines (derived from DiffChange)
- CodeDiffCharMove - character-level highlight for moved text
- CodeDiffMoveFrom - sign/annotation color for move source
- CodeDiffMoveTo - sign/annotation color for move destination
- CodeDiffHelpSection - section headings in keymap help (links to Statement)
- CodeDiffHelpKey - key bindings in keymap help (links to Special)
- CodeDiffHelpSep - separators in keymap help (links to NonText)
- CodeDiffHelpDesc - descriptions in keymap help (links to Normal)

Default behavior:
- Uses DiffAdd and DiffDelete for line-level highlights
- Character-level highlights auto-adjusted based on vim.o.background:
  - Dark themes: brightness multiplied by 1.4
  - Light themes: brightness multiplied by 0.92

Customization examples:
>lua
  highlights = {
    line_insert = "#1d3042",
    line_delete = "#351d2b",
    char_brightness = 1.5,
  }

  highlights = {
    line_insert = "DiffAdd",
    line_delete = "DiffDelete",
    char_insert = "#3fb950",
    char_delete = "#ff7b72",
  }
<

Explorer & history git status highlights (customizable):

- CodeDiffStatusAdded       Added files (links to DiagnosticOk)
- CodeDiffStatusModified    Modified files (links to DiagnosticWarn)
- CodeDiffStatusDeleted     Deleted files (links to DiagnosticError)
- CodeDiffStatusRenamed     Renamed files (links to DiagnosticInfo)
- CodeDiffStatusUntracked   Untracked files (links to DiagnosticInfo)
- CodeDiffStatusConflict    Conflicting files (links to DiagnosticError)
- CodeDiffExplorerSelected  Selected file background (links to Visual)

Override in your config or colorscheme:
>lua
  vim.api.nvim_set_hl(0, "CodeDiffStatusModified", { fg = "#e2c08d" })
  vim.api.nvim_set_hl(0, "CodeDiffStatusAdded", { fg = "#3fb950" })

USER AUTOCMD EVENTS                                     *codediff-events*

CodeDiff emits User autocmd events at key lifecycle points:

*CodeDiffOpen*    Fired after the diff view is fully ready.
*CodeDiffClose*   Fired before cleanup starts.
*CodeDiffFileSelect*  Fired when a file is selected in explorer.

All events pass a `data` table accessible via the autocmd callback's
`args.data` field:

  CodeDiffOpen / CodeDiffClose:
    `tabpage`   Tab page ID of the diff session.
    `mode`      One of "explorer", "standalone", or "history".

  CodeDiffFileSelect:
    `tabpage`   Tab page ID of the diff session.
    `path`      Relative file path selected.
    `status`    Git status code (e.g., "M", "A", "D").

Example: Hide tabline while CodeDiff is open:
>lua
  vim.api.nvim_create_autocmd("User", {
    pattern = "CodeDiffOpen",
    callback = function()
      vim.g.codediff_saved_showtabline = vim.o.showtabline
      vim.o.showtabline = 0
    end,
  })
  vim.api.nvim_create_autocmd("User", {
    pattern = "CodeDiffClose",
    callback = function()
      if vim.g.codediff_saved_showtabline then
        vim.o.showtabline = vim.g.codediff_saved_showtabline
        vim.g.codediff_saved_showtabline = nil
      end
    end,
  })
